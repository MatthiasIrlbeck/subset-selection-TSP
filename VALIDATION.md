# Validation for release 2.0.0

The repository contains two deliberately separate evidence sets:

- `validation_runs/current/` — compact release-health artifacts generated by the current
  executable and current result schema.
- `validation_archive/` — explicitly historical artifacts retained for reproducibility.
  They are never presented as validation of the current release.

The bundled current artifacts are smoke and contract evidence, not publication-scale Monte
Carlo evidence. They show that the release executable runs, emits strict schema-16 output,
preserves deterministic backend parity on small cases, and exercises the documented
benchmark/oracle-routing tools.

## Reproduce the current evidence

```bash
cmake -S . -B build-release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON \
  -DALDOUS_TSP_ENABLE_WARNINGS=ON \
  -DALDOUS_TSP_ENABLE_WERROR=ON \
  -DALDOUS_TSP_ENABLE_PYTHON_TESTS=ON
cmake --build build-release --parallel
ctest --test-dir build-release --output-on-failure

python3 scripts/regenerate_validation_artifacts.py \
  --exe build-release/aldous_tsp \
  --build-dir build-release \
  --output-dir validation_runs/current
python3 scripts/render_validation_report.py \
  --validation-dir validation_runs/current \
  --output docs/known_good_benchmarks.md
```

`regenerate_validation_artifacts.py` replaces the current evidence only after all requested
commands succeed. The generator writes exact project/schema pins and a compact summary.
`validation_artifacts_schema` fails if a current artifact has the wrong project version,
uses an old result schema, contains an environment-specific build path, or is mixed with a
historical artifact.

## Included current checks

The current evidence includes:

- a direct CLI smoke run over subset and full-TSP cells;
- exact grid-versus-brute-force KNN/backend parity;
- a compact benchmark smoke suite;
- final-only versus all-polish exhaustive 2-opt comparison;
- phase/counter profiling output;
- original-CLI-compatible routing against `tests/fake_original_cli.py`;
- a real-oracle discovery manifest.

The ordinary CTest inventory additionally covers the reference oracle integration harness,
strict schema validation, install-tree consumption, schema migrations, quality/hot-path
canaries, campaign manifests, release security, and the C++ unit groups.

## External solvers

No bundled current artifact claims a successful real LKH or Concorde run unless the exact
binary path, version, and SHA-256 are present in that artifact. When neither executable is
available, the current real-oracle manifest records a supported skip. Historical real-LKH
records are retained only under `validation_archive/0.8.7/` and are labelled accordingly.

For a local real-oracle pass:

```bash
python3 scripts/oracle_real_smoke.py \
  --exe build-release/aldous_tsp \
  --schema schema/results.schema.json \
  --lkh-path /path/to/LKH \
  --concorde-path /path/to/concorde \
  --require \
  --out-dir real-oracle-validation
```

The scheduled GitHub workflow downloads only independently hash-approved oracle archives and
fails closed when required digests are absent or do not match.

## Publication claims

A green release-validation run does not establish convergence of the heuristic or support a
numerical claim about the limiting curve. Publication-scale work additionally requires a
frozen campaign manifest, independent point replicates, search-seed calibration, exact or
external-oracle calibration where available, uncertainty decomposition, and finite-size/model
sensitivity analysis. See `docs/reproducibility.md`, `docs/campaign_analysis.md`, and
`docs/limitations.md`.
